# Skill support

> Generated by `node tools/skill-support.mjs` from `reference/reports/fleet.json`. Do not edit it by hand; `--check` fails when it differs.

This page says which of the Hub's 24 skills **reach**, **start on** and **run on** which bodies, as far as a dry test can. It is the skill half of the fleet sweep: 217 public robot descriptions that reached the kernel loop, each asked of every skill. **It is not a statement that any skill works on any robot.** Nothing here was run on hardware, no skill has been judged `success` by the daemon (§54.3) on any body, and a taught pose that lies inside a body's limits is the pose of the body it was taught on, not the pose the task needs.

## 1. What is asked of each skill on each body

| Question | Where it is answered | A "no" means |
|---|---|---|
| **binds** | `skynet skill check --body` → `skill.transport.resolves` | no channel of the skill's action space has an equivalent here (§6, §37.1) — or, for a hand, this body declares none |
| **names** | `skill.context.on_body` | a clause names a joint this body does not have, so §54.2's first rule refuses it with the path named |
| **supplied** | `skill.context.supplied` | a clause reads a path the daemon never fills — today `robot.state.gripper` (`docs/issues/gripper-has-no-open-end.md`) — so the skill never starts on *any* robot |
| **starts** | all three | the skill's preconditions can be evaluated here |
| **driven** | the skill's own `bin/run` through `skynetk --source` on the body | `clean`: every taught row fired, none refused, nothing clamped. `clamped`: every row fired and the kernel clamped some commands (a taught angle past this body's limit). `host refused`: the kernel host will not execute the plan (F218). `failed`: anything else, with the reason in the report |

A hand: the MuJoCo driver declares no end effector (it will not guess a hand from a joint's name), so the sweep, acting as the integrator who accepts a role table (§63.4), declares one — on two grounds, in this order: a joint carries the very role the skill's `gripper` channel names (*by role*), or the body has a joint of exactly the name the skill gives its own gripper joint (*by name*, the rule the planner applies to every other channel). It is recorded on the row (`declared_hand`), and it is the sweep's word, not the scene's. A joint that merely resembles a hand — `Jaw`, `gripper_joint_1` — is not declared.

## 5. `verified_on`

The Hub defines `verified_on` as *robot slugs the publisher has actually verified, not the ones they hope work*. This page is the only place a slug may come from: a skill may name a body there only if its row above shows that skill driven **clean** on it. `node tools/skill-support.mjs --check` refuses a name no row backs.

## 6. What this cannot say, and does not try to

* **That a skill succeeds.** `success_criteria` are judged by the daemon over a state this sweep does not hold (§54.3). A `clean` run means the taught table was executed as published, with nothing refused and nothing clamped; it does not mean the arm reached the pose.
* **That a pose is right on another body.** A taught angle is a measurement of a cell and a body (`docs/issues/skill-clauses-name-one-bodys-joints.md`). A body whose limits contain the number is a body that will execute it, not one that will do the task.
* **Grip force, perception, the physical world.** The sweep drives MuJoCo bodies with no gripper physics worth the name and no objects. 12.F.9 records these as physical-only.
* **Any body not in the fleet.** The page quantifies the public robot descriptions in `fleet/catalogue.json`; a body absent from it is not "unsupported", it is unmeasured.
