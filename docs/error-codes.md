# Error codes

Every machine-readable code the system can emit, and what to do about each. Generated by `skynet explain --dump` — the CLI suite asserts this file matches that output byte for byte, so edit the catalog (`skynet-contracts/src/codes.rs`), never this page.

## `rhal.abi.version`

*check, §15.* The driver reports an RHAL ABI version the running OS supports, and refuses to load against one it does not.

Next: Sim suite, guest tier: rebuild the driver against this OS's RHAL headers and re-run the check.

## `rhal.state.completeness`

*check, §15.* Every joint in the embodiment descriptor appears in the state the driver returns, with matching names.

Next: Sim suite, guest tier: fix the driver's state shape or the descriptor's joint list until the names match.

## `rhal.state.rate`

*check, §15.* Sustained state-read rate over ten minutes, and the worst-case gap between two successive reads.

Next: Bench suite, host tier: book a bench day and measure at the joint; a driver returning success is not evidence.

## `rhal.command.latency`

*check, §15.* Time from a command accepted at the RHAL boundary to measurable joint motion. The number the descriptor must declare.

Next: Bench suite, host tier: measure at the joint, then declare the number — the descriptor must state what this measures.

## `rhal.command.rejection`

*check, §15.* The driver rejects a command naming a joint that does not exist, rather than ignoring it.

Next: Sim suite, guest tier: make the driver refuse unknown joints; silently dropping a channel is the failure.

## `rhal.sensor.latency`

*check, §15.* Per sensor: time from the observed event to the timestamp the frame carries. A backend that stamps arrival rather than capture fails, because a queue delay folded into a timestamp is a number the policy treats as ground truth (§47.2).

Next: Bench suite, host tier: stamp capture, not arrival, per sensor; re-measure at the bench.

## `embodiment.descriptor.valid`

*check, §15.* The descriptor parses, its degrees of freedom match its joint list, and every declared role is well formed.

Next: Sim suite, guest tier: fix the descriptor — `skynet descriptor from-urdf` drafts one, `skynet role` checks a role.

## `embodiment.descriptor.signed`

*check, §15.* The descriptor carries a signature that verifies against a key registered to the vendor namespace.

Next: Sim suite, host tier: get the vendor's signature on the descriptor, or register the key it carries.

## `embodiment.limits.sourced`

*check, §15.* Every declared limit cites a source. A rating with no provenance fails, because the safety kernel would be enforcing a rumour.

Next: Sim suite, host tier: cite the datasheet per limit; an unsourced rating is a descriptor to fix, not evidence to argue.

## `embodiment.limits.honest`

*check, §15.* Measured joint velocity and torque against the declared ratings under load. A body that cannot reach what it claims fails as surely as one that exceeds it.

Next: Bench suite, certified tier: measure under load at the bench; then either derate the descriptor or fix the machine.

## `embodiment.roles.coverage`

*check, §15.* Share of actuated joints carrying a canonical role. Below full coverage, cross-body transport degrades to exact-name matching.

Next: Sim suite, host tier: fill in canonical roles — `skynet role left_arm.shoulder.pitch` checks one spelling at a time.

## `embodiment.capabilities.declared`

*check, §15.* Every capability token the descriptor declares is one the driver can actually service, and every token a resident package requires appears in the list. The set is what admission checks a package against (§8), so a body claiming a capability it does not have admits a package that will command hardware nobody fitted.

Next: Sim suite, host tier: declare exactly what the driver services — no more, or admission passes packages the body cannot run.

## `embodiment.frames.complete`

*check, §15.* The descriptor carries a §44.3 frame graph that is a single rooted tree, every dynamic node names a joint the descriptor declares, every mimic names a driver present in the tree, and every collision shape is one this edition can evaluate. Absent or null is not a failure of this test — it is the two pose guards reporting unavailable, which §44.5 permits — but a graph that is present and wrong is.

Next: Sim suite, host tier: fix the frame graph, or delete it and let the pose guards report unavailable honestly.

## `safety.kernel.parity`

*check, §15.* The on-robot kernel and the reference implementation return identical verdicts across the full cycle-vector corpus.

Next: Sim suite, guest tier: a kernel divergence is an OS defect, not a driver defect — file it with the vectors that differ.

## `safety.watchdog.fires`

*check, §15.* Commands are stopped mid-motion; time until the robot reaches a controlled stop, against the declared watchdog window.

Next: Bench suite, host tier: measure mid-motion at the bench; a stop slower than declared is a watchdog to fix, not a window to widen.

## `safety.envelope.clamps`

*check, §15.* A command at 150% of a joint rating is issued; the joint never exceeds its rating, measured at the joint rather than reported by the driver.

Next: Bench suite, host tier: measure at the joint; a clamp that reports without clamping fails here by design.

## `safety.estop.latency`

*check, §15.* Time from estop assertion to zero commanded torque. Measured at the actuator; a driver reporting success is not evidence.

Next: Bench suite, host tier: measure at the actuator and shorten the path until the number holds.

## `safety.estop.independent`

*check, §15.* The application processor is halted mid-motion. The robot must still stop, proving the stop path does not run through it.

Next: Bench suite, certified tier: this needs stop hardware independent of the application processor — a board revision, not a parameter.

## `safety.ratelimit.enforced`

*check, §15.* A single-cycle step from zero to full scale produces a ramp at the configured jerk ceiling, not a step.

Next: Bench suite, host tier: configure the jerk ceiling and re-measure; a step through is a rate limiter missing, not misconfigured.

## `safety.command_loss.behaviour`

*check, §15.* Commands stop and the drives are observed at the joint. What they do must be what the body declares — `on_command_loss` for the whole body, or `on_command_loss_by_chain` per §5.1 chain, and a body that declares both is refused before it is measured (§46.2, §87.3). Every chain is observed, because a humanoid may brake on the legs and coast on the arms and a measurement of one leg is not evidence about an arm. A body observed to coast may not claim host, because the watchdog chain’s own recovery path is, on that machine, a fall.

Next: Bench suite, host tier: declare one behaviour, observe every chain, and do not claim host on a body that coasts.

## `safety.homing.envelope`

*check, §15.* The driver-provided homing procedure is run and the joints are watched. No joint exceeds the restricted homing envelope the descriptor declares (§48.3). Homing is not an exemption from the kernel; it is a narrower envelope. A body that declares it needs no homing records not_applicable.

Next: Bench suite, host tier: declare the restricted envelope and re-run; or declare no homing and record not_applicable.

## `safety.policy.isolation`

*check, §15.* A sandboxed package holding an actuator file descriptor is refused; the sandbox has no path to one.

Next: Sim suite, guest tier: a package reaching an actuator descriptor is a sandbox hole — file it, do not work around it.

## `package.signature.required`

*check, §15.* An unsigned package, and one whose bytes do not match its digest, are both refused.

Next: Sim suite, guest tier: sign the package and match its digest; the refusal is the gate working.

## `package.budget.enforced`

*check, §15.* A package exceeding its declared memory budget is stopped rather than allowed to exhaust the robot.

Next: Bench suite, host tier: declare the budget the package needs, or fix the leak — the stop is the enforcement.

## `package.grants.gate`

*check, §15.* A package commands a capability the operator did not grant; the mode gate refuses it and the refusal is logged.

Next: Sim suite, guest tier: grant the capability or remove the command; the log entry is the audit trail, keep it.

## `ota.rollback.works`

*check, §15.* A deliberately broken image is staged; the robot boots it, fails its health check, and returns to the previous slot unattended.

Next: Bench suite, host tier: this exercises the rollback path end to end — a robot that stays broken fails its own safety net.

## `ota.safe_state.respected`

*check, §15.* An update issued mid-task is staged and not applied until the robot reaches a declared safe state.

Next: Bench suite, host tier: declare the safe state and re-run mid-task; an update that applies early fails here by design.

## `ota.safety_gate`

*check, §15.* An update changing the safety kernel or the envelope is refused without a fresh bench pass. OTA must not be a route around certification.

Next: Sim suite, host tier: bench the changed kernel or envelope first — the refusal is certification defending itself.

## `telemetry.blackbox.complete`

*check, §15.* Every cycle in a ten-minute run appears in the black box with observation hash, policy output, kernel verdict and final command.

Next: Bench suite, host tier: a gap in the recording is a recorder defect — find the dropped cycles, not an excuse for them.

## `telemetry.replay.deterministic`

*check, §15.* Replaying a sealed recording through the same policy digest and embodiment digest reproduces the same actions.

Next: Sim suite, host tier: a replay that diverges names what the recording failed to capture — record it, then re-run.

## `telemetry.blackbox.survives`

*check, §15.* Power is cut mid-motion; the black box up to the last completed cycle is intact after reboot.

Next: Bench suite, certified tier: cut power mid-motion and read back the seal — anything less than the last cycle is data loss.

## `offline.control.independent`

*check, §15.* The network is removed mid-task. The robot completes the task. No control decision may require a round trip.

Next: Bench suite, guest tier: remove the network mid-task; anything that stalls was a control decision with a round trip in it.

## `offline.control.remote_holds`

*check, §90.3.* The network is removed mid-task under a remote policy. The robot reaches a controlled hold within the package's declared `max_chunk_age_ms` plus the watchdog period, no command older than that deadline reaches the command ring, and motion does not resume until a new session delivers a chunk and the operator profile's resume rule is met.

Next: Bench suite, guest tier, remote policies only: pull the network mid-task and time the hold; a late hold, a stale command on the ring, or motion before the resume rule is met fails.

## `offline.reconcile.resumes`

*check, §15.* After a week offline the robot reconciles to desired state and uploads its backlog without operator action.

Next: Bench suite, host tier: go dark for a week-equivalent and watch it come back alone; anything needing a hand fails.

## `security.identity.attested`

*check, §15.* The device key is held in a secure element or TPM and check-ins carry an attestation of the running image digest.

Next: Sim suite, host tier: bind the device key to hardware attestation; a software-held key fails by design.

## `security.credential.scope`

*check, §15.* A device credential lifted from the robot cannot read repositories, claim jobs, or write to another namespace.

Next: Sim suite, guest tier: scope the credential to this device's namespace; anything wider fails the lift test.

## `power.safe_state.reachable`

*check, §15.* From full rated load, the robot is taken to its nearest safe state and timed, against the `time_to_safe_state_s` it declares (§36.2). The reserve budget is computed from that figure, so a body that declares two seconds and takes six has a third of the reserve it needs.

Next: Bench suite, host tier: time it from full load and declare honestly — the reserve is computed from the declaration.

## `unsigned`

*refusal, §8.* No publisher signature accompanied the package.

Next: Sign the package; an unsigned package is refused, not warned about.

## `signature_failed`

*refusal, §8.* A signature was present and did not verify — the one signature state that says something went wrong rather than something is missing.

Next: Stop: fetch the package from the publisher again and compare digests. Do not install.

## `signature_untrusted`

*refusal, §8.* A signature verified, and the key that made it is not one this robot trusts. Nothing is wrong with the bytes; what is missing is an operator's decision.

Next: Decide: trust the signer's key on this robot, or refuse the package. There is no third option.

## `signature_unverifiable`

*refusal, §8.* This platform cannot verify a signature at all — a gap in the operating system rather than in the package.

Next: File against the OS. The package is fine; the platform cannot check it.

## `digest_mismatch`

*refusal, §8.* The bytes do not hash to the digest in the manifest.

Next: Re-download; install nothing whose bytes disagree with its manifest.

## `isolation_violation`

*refusal, §8.* A non-driver asked to run unsandboxed.

Next: Sandbox the package; only drivers run outside the sandbox.

## `budget_exceeded`

*refusal, §8.* The robot cannot supply the declared budget.

Next: Raise the robot's budgets or lower the package's declaration.

## `capability_ungranted`

*refusal, §8.* A capability is unprovided by the body, or awaiting an operator grant.

Next: Fit the hardware, grant the capability, or drop the request.

## `capability_denied`

*refusal, §8.* The operator profile withholds a capability the package requires.

Next: Change the operator profile, or run a package that needs less. Denied is reversible; reserved is not.

## `over_request`

*refusal, §8.* The package requests a permission it never declared a need for.

Next: Declare the need in the manifest, or drop the request.

## `missing_dependency`

*refusal, §8.* A declared dependency is not installed.

Next: Install the dependency, then re-run admission.

## `os_too_old`

*refusal, §8.* The robot's OS predates the package's minimum.

Next: Update the OS to the package's minimum first.

## `transport_refused`

*refusal, §8.* The policy's action space cannot be transported onto this body.

Next: Read the transport plan's warnings; the body and the policy disagree about the action space.

## `executes_on_load_untrusted`

*refusal, §8.* Files execute code when read, and the operator has not accepted that.

Next: Accept the risk explicitly, or repackage without executable-on-load files.

## `environment_inert`

*refusal, §8.* An environment package on a robot with no simulator driver, which will never load it (§55.1).

Next: Fit a simulator driver, or install the package where one exists.

## `capability_reserved`

*refusal, §8.* The package asked for a capability no grant can ever confer (§49.1). Denied is reversible; this has no setting behind it.

Next: Remove the request. No operator action grants it, by design.

## `embodiment_undeclared`

*refusal, §8.* The manifest declares requirements the `embodiment` block does not, so nothing enforced them.

Next: Declare requirements in the `embodiment` block — the Hub's fields on the same document are not enforced.

## `capability_unknown`

*refusal, §8.* The requested capability is outside every known vocabulary — usually a typo, and the fix is in the manifest.

Next: Fix the token spelling in the manifest; the robot is not missing hardware.

## `policy_source_invalid`

*refusal, §90.2.* The install names a policy source that is neither local nor hosted, or asks a package that is not a policy to infer on a hosted endpoint. Only a policy's forward pass may run elsewhere.

Next: Set the desired state's policy_source to local or hosted, and hosted only on a policy.

## `deadline_undeclared`

*refusal, §90.2.* Something that must run under a deadline declares none: a policy installed to infer elsewhere with no serving.max_chunk_age_ms, a remote session, or a motion (§87.4). The robot is not asked to invent one.

Next: Declare the deadline — for a hosted policy, serving.max_chunk_age_ms in the published manifest — and install again.

## `network_dependent`

*refusal, §90.4.* A warning on every hosted install: the policy infers on a hosted endpoint, the robot holds when the link drops, and it cannot hold the Certified tier (§90.4).

Next: Nothing to fix. Decide whether this robot's work may depend on a link; if not, install the policy to infer locally.

## `no_source_embodiment`

*warning, §84.* The policy declares no action space at all.

Next: Declare the policy's action space; there is nothing to transport without it.

## `unverified_embodiment`

*warning, §84.* The body description is not signed by its vendor.

Next: Get the vendor signature, or accept an unverified body deliberately.

## `no_target_envelope`

*warning, §84.* The body declares no safety envelope.

Next: Declare the envelope; guards without one report unavailable.

## `dof_mismatch`

*warning, §84.* Training and target degrees of freedom differ.

Next: Retarget across the gap, or train for this body.

## `control_mode_unsupported`

*warning, §84.* The body does not accept the mode the policy emits.

Next: Emit a mode the body accepts, or fit a driver that translates.

## `rate_unsupported`

*warning, §84.* The policy's rate exceeds what the body accepts, so the loop is clamped.

Next: Lower the policy rate, or accept running clamped.

## `rate_below_watchdog`

*warning, §84.* The resolved loop is slower than the controller's watchdog window.

Next: Raise the rate above the watchdog window; a slower loop trips it.

## `scaled_down`

*warning, §84.* A channel is scaled down to stay inside a joint rating.

Next: None required — but the policy runs derated, so validate it derated.

## `unscalable_channel`

*warning, §84.* A channel cannot be scaled because one of the two figures is missing.

Next: Supply the missing figure: the policy's limit or the joint's rating.

## `retarget_without_solver`

*warning, §84.* Task-space retargeting is needed and unavailable.

Next: Fit a retargeting solver, or transport joint-to-joint.

## `unmapped_roles`

*warning, §84.* Joints on this body that the policy does not drive.

Next: Map roles for the undriven joints, or hold them deliberately.

## `observation_missing`

*warning, §84.* A required observation stream has no equivalent.

Next: Fit the sensor, or retrain without the stream.

## `observation_degraded`

*warning, §84.* An observation stream is present but poorer than the trained one.

Next: Validate the policy against the poorer stream before trusting it.

## `latency_undeclared`

*warning, §84.* The body declares no command latency.

Next: Declare the latency; the loop assumes nothing.

## `action_space_mismatch`

*warning, §84.* The policy and the body do not command the same kind of action space (§84.3).

Next: Align the action-space kinds, or transport through task space.

## `action_space_ambiguous`

*warning, §84.* The policy declares both joint channels and named motions (§84.2).

Next: Declare one: joints or motions, not both.

## `motion_parameter_unused`

*warning, §84.* A motion binds, and a parameter the policy supplies is one the body's motion does not take.

Next: Drop the parameter, or pick a motion that takes it.

## `joint_mode_conflict`

*warning, §86.* Two channels command one joint in two modes (§86.2).

Next: Command each joint in one mode.

## `mixed_modes_unsupported`

*warning, §86.* The body is commanded in two modes and its driver reads one per command (§86.1).

Next: Use one mode for the body, or a driver that reads per-joint modes.

## `travel_one_end`

*warning, §7.* A joint bound in position declares one end of its travel and not the other, so the Safety Kernel bounds its position by nothing.

Next: Declare both position_min_rad and position_max_rad for the joint in the body description.

## `gauge_silent`

*fault, §36.* The body declares a pack and nothing read one.

Next: Check the gauge wiring and driver; a declared pack with no reading is a sensor fault.

## `capacity_undeclared`

*fault, §36.* The gauge reports a fraction and the body declares no capacity to scale it by.

Next: Declare the pack capacity.

## `reserve_undeclared`

*fault, §36.* A pack is claimed and no safe-stop energy is declared, so there is no reserve.

Next: Declare the safe-stop energy; without it there is no reserve.

## `brownout_undeclarable`

*fault, §36.* The RHAL is degraded and this vendor has declared no code that means sag (§36.4).

Next: Declare the vendor's sag code, or accept brownouts the OS cannot name.

## `charge_out_of_range`

*fault, §36.* The gauge reports a state of charge outside 0–1.

Next: Fix the gauge; a charge outside 0–1 is a broken reading.

## `thermal_sustained`

*fault, §36.* Above the throttle temperature for longer than the sustained window — and it raises DEGRADED.

Next: Cool the machine or shed load; sustained heat degrades the robot by rule.

## `thermal_critical`

*fault, §36.* Above the critical temperature — and it raises DEGRADED.

Next: Stop and cool: critical heat is a stop condition, not a warning to watch.

## `thermal_undeclared`

*fault, §36.* A temperature arrived and the body declares no threshold to compare it against.

Next: Declare the thermal thresholds.

## `device_signature`

*reason, §56.* The device's signature over the bundle is not one the Hub trusts.

Next: Register the device key with the Hub, or re-sign from a known device.

## `device_unknown`

*reason, §56.* The signature verifies and the Hub does not know the device.

Next: Enroll the device; a valid signature from a stranger attests nothing.

## `simulator_declared`

*reason, §56.* The driver declared itself a simulator (§35.3). Not a fault — the declaration is the driver meeting its obligation.

Next: None. Expect sim-capped tiers wherever this reason appears.

## `birth_unattested`

*reason, §56.* The robot's birth certificate does not attest it (§50).

Next: Attest the birth certificate; the birth findings name the failing field.

## `image_unattested`

*reason, §56.* The running OS image was not attested.

Next: Boot an attested image; the running one proves nothing about itself.

## `seeds_not_supplied`

*reason, §56.* The seeds are not the benchmark's (§56.3).

Next: Run the benchmark's seeds; other seeds measure another experiment.

## `benchmark_mismatch`

*reason, §56.* The bundle's benchmark figures disagree with the benchmark's declaration.

Next: Re-run under the declared benchmark conditions.

## `not_replayable`

*reason, §56.* No black box segment accompanies the run (§56.4). Reported and never class-changing.

Next: Attach the black box segment for replay; without it the result stands without replay evidence.

## `unnamed`

*fault, §84.1.* A motion — or one of its parameters — has an empty name, and a name is what a command carries.

Next: Name it.

## `duplicate_motion`

*fault, §84.1.* Two motions share a name, so a command naming it is ambiguous.

Next: Rename one; command names must be unambiguous.

## `unknown_motion`

*fault, §84.1.* A motion claims a canonical name that is not one. Omit the field for a motion that is none of them.

Next: Omit the canonical field, or spell a canonical motion.

## `duplicate_parameter`

*fault, §84.1.* A motion lists one parameter twice.

Next: List each parameter once.

## `required_undeclared`

*fault, §84.1.* A parameter does not say whether it is required. It is read as required, which refuses plans that omit it.

Next: Declare required true or false on the parameter.

## `bound_invalid`

*fault, §84.1.* A parameter declares a bound that is not a finite number, or a minimum above its maximum.

Next: Declare finite bounds with the minimum below the maximum.

## `unknown_stream`

*refusal, §47.* A frame from a stream this pool does not hold.

Next: Publish to a stream the pool holds, or grow the pool.

## `unknown_slot`

*refusal, §47.* A handle naming a slot outside this pool, or another pool's stream.

Next: The handle is stale or foreign; re-acquire from this pool.

## `stale_handle`

*refusal, §47.* The slot has been reused since the handle was issued.

Next: Re-acquire; the frame the handle named is gone.

## `already_acquired`

*refusal, §47.* The handle is already checked out; a handle is one loan, not a share.

Next: Release before re-acquiring; a handle cannot be shared.

## `double_release`

*refusal, §47.* The handle was already released.

Next: Release once; the second release is the bug.

## `pool_exhausted`

*refusal, §47.* Every slot is acquired, so capture's frame was dropped and counted — the one refusal here that is a normal operating condition.

Next: Drain faster or grow the pool; drops are counted, not hidden.

## `empty`

*fault, §18.* Nothing was given.

Next: Type the code from the robot's screen.

## `looks_like_a_credential`

*fault, §18.* This is the credential pairing hands back, not the code it takes.

Next: Paste that string where a credential belongs, and type the short code here.

## `too_short`

*fault, §18.* Fewer than eight characters.

Next: Type all eight characters, both groups.

## `too_long`

*fault, §18.* More than eight characters.

Next: Type just the code — eight characters, nothing around it.

## `not_in_alphabet`

*fault, §18.* A character no code uses, even after folding. The fault names the position.

Next: Retype the named position; excluded letters are folded, anything else is a mistype.

## `unattested`

*finding, §50.* The certificate establishes nothing at all.

Next: Re-issue the birth certificate; nothing below it can be evaluated.

## `device_key_mismatch`

*finding, §50.* The secure element holds a different key from the one the certificate was issued over — the mainboard-swap case (§50.4), and the most serious of the mismatches.

Next: Re-issue after a mainboard swap; otherwise treat it as tampering.

## `serial_mismatch`

*finding, §50.* The serial does not match: what the certificate says, then what the machine reports.

Next: Check which serial moved — the finding lists certificate first, machine second.

## `descriptor_mismatch`

*finding, §50.* The descriptor this robot is running is not the one the vendor attested.

Next: Run the attested descriptor, or get the vendor's attestation on this one.

## `hardware_revision_mismatch`

*finding, §50.* The hardware revision does not match: the revision the certificate names, then the one the machine reports.

Next: Check the revision on both sides; they must agree.

## `ownership_asserted`

*finding, §50.* The certificate asserts something about ownership, which is not the vendor's to assert.

Next: Strip the ownership assertion; vendors attest hardware, not owners.

## `unobservable`

*finding, §50.* A field the certificate binds that the robot could not observe.

Next: Make the field observable, or drop it from the certificate.

## `incomplete`

*finding, §50.* The certificate is missing a field it must bind (§50.2).

Next: Bind the missing field.

## `advisory_only`

*notice, §7.* The tier cannot enforce; verdicts are recorded and nothing is stopped.

Next: Raise the tier for enforcement, or accept recorded-but-unenforced verdicts.

## `no_envelope`

*notice, §7.* No safety envelope was declared for this robot.

Next: Declare the envelope; without it every guard that needs one is unavailable.

## `no_independent_stop`

*notice, §7.* No stop path exists that survives the application processor hanging.

Next: Fit an independent stop path — certified-tier hardware, not a parameter.

## `unsourced_limits`

*notice, §7.* The declared limits cite no datasheet.

Next: Cite the datasheet per limit.

## `guard_unavailable`

*notice, §7.* A guard cannot run here; the subjects name the missing inputs.

Next: Supply the named inputs.

## `profile_widened`

*notice, §7.* The operator profile asked to raise a limit. The request was recorded and discarded.

Next: None — raising limits by profile is refused by design.

## `no_rate_limit`

*notice, §7.* No jerk ceiling is configured.

Next: Configure the jerk ceiling.

## `no_collision_margin`

*notice, §7.* No self-collision margin is configured, so surfaces must meet before the guard trips.

Next: Configure the margin; zero margin means contact is the trip.

## `session_override`

*notice, §7.* A session override (§38.2) is narrowing this robot — printed on every surface until it clears or expires.

Next: Clear the override when maintenance ends, or let it expire.

## `session_widened`

*notice, §7.* A session override asked to raise a limit. The request was recorded and discarded.

Next: None — overrides narrow only, by design.

## `travel_widened`

*notice, §7.* The operator profile asked to widen a joint's travel past what the body declares. The wider ends were discarded; the travel in force is where the two ranges overlap.

Next: None — a profile narrows a travel and never widens it. Correct the profile's joint_travel if the range was a mistake.

## `travel_empty`

*notice, §7.* No position is inside every range that bounds a joint's travel, so there is nothing to clamp a command to. A policy commanding it is refused.

Next: Correct the profile's joint_travel so it overlaps the travel the body declares.

## `package.manifest.present`

*check, §8.* manifest.json at the package root.

Next: Put manifest.json at the package root.

## `package.manifest.decodes`

*check, §8.* Decodes as a package manifest (§8).

Next: Fix the manifest until it decodes.

## `package.kind.skill`

*check, §8.* `kind` is `skill`.

Next: Set kind to skill — this check only checks skills.
