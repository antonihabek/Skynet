# Editions

Skynet OS is a specification with implementations, not an implementation with a specification
attached. An **edition** is one implementation of it in one language, and every edition is held to
the same thing: the conformance corpus in [`../corpus/`](../corpus/), byte-for-byte (§31.4).

> *"An edition that has not passed the corpus is not an edition. It cannot carry the name, appear
> in the matrix, or be installed by `skynetd`."*

## Where each one lives

| Edition | Path | Reproduce the corpus |
|---|---|---|
| **Rust — the reference** | [`../crates/`](../crates/) | `cargo test -p skynet-corpus` |
| Python | [`python/`](python/) | `python3 editions/python/run_corpus.py` |
| C++ | [`cpp/`](cpp/) | `make -C editions/cpp check` |
| Go | [`go/`](go/) | `make -C editions/go check` |
| C | [`c/`](c/) | `make -C editions/c check` |
| Zig | [`zig/`](zig/) | `zig build --build-file editions/zig/build.zig check` |
| Java | [`java/`](java/) | `make -C editions/java check` |
| C# / .NET | [`csharp/`](csharp/) | `make -C editions/csharp check` |

Every command runs from the repository root, and CI runs the same ones.

## Why Rust is not in this directory

Because it is not a peer of the others, and putting it here would say it is.

The corpus is generated from the TypeScript oracle in [`../reference/`](../reference/), and the
Rust edition is the **reference edition**: the first held to it, and the one that ships the
operating system itself — the Safety Kernel (`no_std`, no allocator), the control
loop, the supervisor, the CLI and the installer all come out of `crates/`. The other editions are
**contract** editions (§42's L2): they compute the same verdicts from the same inputs, so a vendor
whose stack is C, Go or .NET can check an admission decision, a transport plan or a predicate in
their own language and get the answer the robot will get.

## Which ones are complete

Not written here, on purpose. A README that states a passing figure is a claim with nothing behind
it, and it drifts the first time the corpus grows. Two sources say it instead, and both are the
output of actually running the editions:

* each edition's runner prints its own figure on every run;
* [`../reference/reports/editions.json`](../reference/reports/editions.json) is generated by
  `tools/edition-report.mjs` and lists the editions that pass the whole corpus.

What each language *could* reach — its tier ceiling and standing — is §31.3's matrix in the
specification, and it is a property of the language rather than of how far an edition has got. A
garbage-collected edition is an observer at Guest tier however complete it is, because a collector
cannot promise a clamp inside a 1 ms deadline.

## Adding one

Read §31 first, then the smallest complete edition beside it. An edition starts by round-tripping the
corpus's own canonical JSON byte-for-byte, and grows one corpus file at a time — its runner
reporting a partial figure honestly the whole way. It becomes a CI step as soon as it has a runner,
at a `--min-passed` ratchet that only ever rises. [`../CONTRIBUTING.md`](../CONTRIBUTING.md) has the rest.
